02 · Architecture

The model understands; code decides

UNDERSTAND · learned, probabilistic

Channels

Web chat with a live trace; Slack and Telegram adapters over one bridge.

Learned router

Intent, language and prompt injection; abstains when unsure.

LLM extraction

gemma-4-31b reads amount, merchant, dates. PII redacted; never sees ID or OTP.

DECIDE AND ACT · deterministic, auditable

State machine

10 stages, each with its own tool allowlist.

Policy P1–P8

Versioned rules decide when a human must.

Bank tools

OTP auth, scoped reads, writes read back.

Reply or handoff

Verified facts only, or a JSON handoff.

A write happens only if the session is verified, policy allows it, rules and model both read a clear “yes”, and the record reads back. Every turn is traced.

The core design choice: the model understands, code decides. The top row is the probabilistic part: a learned router for intent, language and prompt injection, and an LLM that extracts amounts, merchants and dates. The LLM never sees the document number or the OTP, and personal data is redacted before it. The bottom row is deterministic: a state machine where each stage can only call its own tools, a versioned policy for when a human must decide, and bank tools that are scoped to the authenticated customer. When the router and the LLM disagree, the agent asks the customer instead of guessing. And a write needs a verified session, a policy yes, both the rules and the model reading a clear yes, and a read-back check.
